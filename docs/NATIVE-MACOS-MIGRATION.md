# Native macOS migration

## Status

GodEye's macOS target uses SwiftUI and AppKit, a Metal globe, native Foundation networking, and AVFoundation/AVKit media playback on Apple Silicon. It contains no WebKit, Electron, browser shell, HTML interface, JavaScript renderer, local server or Node application runtime. The orbital and 3D tile engines are compiled C++, called directly from Swift. Python and CMake support native builds. The optional Sentinel-1 processing workflow also invokes a separately configured Python raster worker and ESA SNAP GPT; neither is embedded in the interface or bundled as a browser/server runtime.

**The full functional migration is still incomplete.** This continuation adds a real native terrain and photorealistic 3D Tiles engine to the existing native data and workspace ports. Additional providers, complete 3D format/material support and calibrated camera projection remain. The native interface identifies incomplete parity. The web implementation and its tests remain intact as the reference, and are not packaged in the app.

Bike share, radio, cockpit, voice and San Francisco neighborhood boundaries remain excluded at the owner's request. AI object detection, general investigation management and other proposed roadmap additions remain outside this migration. The subsequently implemented [satellite infrastructure review workspace](SATELLITE-INFRASTRUCTURE-REVIEW.md) provides scoped site/pair/candidate review and does not imply general investigation parity. The subsequently requested Sentinel-1 GRD processing workflow is documented separately in [SENTINEL1-SAR.md](SENTINEL1-SAR.md); it requires external processing tools and real-product validation. Local annotations and view/workspace documents are existing capabilities being ported; they are not an investigation/evidence system.

## Build and run

Requirements: an arm64 Mac, Xcode with the macOS SDK and Metal compiler, CMake 3.24+, Python 3, pkg-config, and macOS 14 or later. Homebrew `cmake` and `pkgconf` provide the extra native build prerequisites. Validation was performed on this arm64 Mac running macOS 27; a separate macOS 14 machine has not been tested.

From the repository root:

```sh
native/macos/build-app.sh
native/macos/test.sh
xcrun swift-format lint --strict --recursive native/macos/Sources native/macos/Tests native/macos/Package.swift native/macos/Icon.swift
```

Optional public-provider checks make actual network requests:

```sh
GODEYE_LIVE_CHECKS=1 native/macos/test.sh --filter Live
```

Open `output/native/GodEye.app` in Finder. The build packages the arm64 release executable, Swift resource bundles, precompiled Metal shader, icon and component/data licenses, and checks a local ad-hoc signature. It does not install anything into Applications, publish the app, or produce a Developer ID signed/notarized distribution.

`npm run macos:build`, `npm run macos:test` and `npm run macos:format:check` are optional development shortcuts. Node is not used by the delivered application.

## Remaining migration work

- Additional terrain/3D providers (including ion/Google authentication and required provider attribution), quantized-mesh terrain, full material/format coverage, improved terrain/imagery LOD transitions and broader dataset validation.
- Remaining camera provider catalogs, calibrated pose controls and image/video projection onto real scene geometry.
- Matched mission orbit records and complete mission/recovery/timeline presentation; full dense catalog and tracking interaction parity.
- Additional map/provider settings and imagery-selection behavior, including legacy fallback stacks and clear-scene workflows.
- Regional/global context staging, complete contacts workflows, full style coverage and legacy web share compatibility.
- Complex OSM relation geometry and broader contextual discovery.

CesiumJS cannot be retained under the no-WebKit requirement. [Cesium Native's rendering integration](https://cesium.com/learn/cesium-native/ref-doc/rendering-3d-tiles.html) supplies selection/loading but requires an application renderer and resource preparation. GodEye now supplies the native Metal mesh renderer and renderer-resource preparation through an Objective-C++ bridge. Cesium Native selects and loads the tiles; Foundation NSURLSession supplies networking. No CesiumJS or web renderer is packaged.

## Terrain and photorealistic 3D Tiles continuation — October 4, 2026

Open **3D Surface** in the native toolbar. Terrain is enabled by default and begins loading below a 200 km camera range. The panel supplies tilt/heading sliders, north-up, local `tileset.json` loading, HTTPS URL loading, coverage focus/removal and visible source credits. Option-drag rotates/tilts the camera. Clicking the surface inspects its coordinates, rendered height and the geometry source. A tileset stays in the current session; its URL/local path is not exported or put in view links.

### Real sources and implemented rendering

- **Keyless elevation:** [Mapzen terrain on AWS](https://registry.opendata.aws/terrain-tiles/), using the documented [Terrarium RGB encoding](https://github.com/tilezen/joerd/blob/master/docs/formats.md). ImageIO validates 256×256 images before decompression, and source channel values are read without color conversion. Fractional and negative values are retained; displayed ocean terrain is clamped to sea level. Full [source attribution](https://github.com/tilezen/joerd/blob/master/docs/attribution.md) is bundled and accessible in the native panel.
- **Actual photogrammetry:** the public AGI headquarters tileset listed in [Cesium's 3D Tiles resources](https://github.com/CesiumGS/3d-tiles/blob/main/RESOURCES.md) is available directly from the panel. It loads captured textured buildings and ground geometry. The app also accepts georeferenced local and same-origin HTTPS 3D Tiles; it does not create mock buildings or simulated scenery. Public availability is not a blanket redistribution license.
- **Native engine:** [Cesium Native v0.65.0](https://github.com/CesiumGS/cesium-native/tree/v0.65.0), pinned to `1bca8021711294cc83a5a032599ac72d9b3166c9`, provides hierarchical selection, screen-space-error refinement and native glTF decoding. GodEye supplies native background jobs, bounded NSURLSession access, double-precision georeferencing and the Metal renderer. The app has no embedded web engine or service process.
- **Depth and precision:** an infinite-far reverse-Z projection uses one double-precision camera basis for rendering and picking. Terrain/mesh vertex buffers have local origins and receive camera-relative offsets. This avoids globe-coordinate precision loss in close views. Fine raster regions replace their parents in both depth rendering and picking; terrain boundary vertices conform to their loaded parent surface.
- **Draping and navigation:** raster imagery and NASA overlays use the terrain triangles. Surface routes, annotations and selected outlines follow the actual rendered terrain grid. Records with unknown altitude are positioned for display on the loaded ground; a reported altitude is not replaced or written back as inferred data. Camera range is relative to the loaded target surface, and clearance checks the geographically displaced eye at the current tilt/heading. Following and route navigation use the same clearance check.
- **Picking:** terrain tests the exact uploaded raster triangles. 3D picking tests prepared mesh triangles, material cutouts/back faces and the subset actually uploaded to the GPU. An invisible/unprepared or memory-rejected mesh cannot be selected. Heights shown in the inspector describe the rendered geometry, rather than a provider measurement or an invented observation time.
- **Textures:** baked base-color photogrammetry, base-color factors, indexed triangles, triangle strip/fan conversion, UV sets, `KHR_texture_transform`, sampler wrap/filter modes, mipmaps, sRGB texture colors, opaque/masked/blended material handling and double-sided geometry are implemented. Geometry/content preparation remains asynchronous; unsupported or oversized content is counted as a failure.

### Bounds and current limits

Visible raster/terrain selection includes the tilted view footprint and the displaced eye, with coarse coverage plus detail near the target/eye, at most 81 requested tile IDs per selection and a terrain zoom cap of 14. Elevation storage holds at most 96 decoded tiles. Four elevation requests and four 3D tile requests can run concurrently. 3D request bodies are capped at 32 MB; copied mesh/texture preparation has a 64 MB per-content budget, the native tile cache targets 128 MB and uploaded 3D GPU resources are capped at 256 MB. These are component budgets, not a hard total process-memory guarantee. PNG/JPEG decoder dimensions are capped at 8192 before allocation; other upstream compressed-content decoders still need broader adversarial validation. Standard HTTP caching applies to terrain/raster imagery; this is not a bulk/offline download tool.

The terrain model mixes source vertical datums and acquisition vintages. It has no installed geoid correction and is not a survey-grade elevation service. Unknown terrain remains an explicit ellipsoid fallback, including polar areas outside Web Mercator coverage. Camera clearance applies to loaded geometry at the current view, rather than guaranteeing clearance through unloaded terrain/buildings. Provider mosaics can have visible color/resolution seams between imagery levels. Elevation-edge conforming reduces mesh gaps but is not a complete multi-resolution terrain geomorphing system.

The renderer currently targets georeferenced triangle photogrammetry. Full physically based lighting, normal/metallic/roughness materials, point clouds, splats, instanced tiles, structural feature metadata/semantic building identifiers, and all optional 3D Tiles extensions are not complete. Alpha picking uses the base texture level; a mip-filtered silhouette can differ at distant screen pixels. Blended meshes are sorted by origin distance; intersecting translucent surfaces are not fully order-independent. A custom dataset's correctness is not established simply because it loads.

Local references are restricted to the chosen tileset directory/subdirectories (including symlink resolution); network assets/redirects stay on the selected HTTPS origin. Cross-origin texture/CDN datasets and authenticated ion/Google provider flows are not included yet. No paid provider key is required for the implemented terrain or public AGI coverage. Data/component licenses remain separate from the project's MIT license. The generated app includes `SCENE-NOTICES.txt`; the build downloads dependencies only into development caches, not the app bundle.

The first engine build needs network access and can take several minutes. `build-engine.sh` uses an arm64/macOS 14 dependency triplet, pins source/dependency revisions and reuses subsequent builds. A generated archive fingerprint ensures SwiftPM relinks when the external C++ engine changes. Development dependency builds may emit harmless empty-object archive warnings; these do not replace build/signature validation. macOS 14 deployment flags are used throughout, but runtime testing on a separate macOS 14 Mac remains outstanding.

## Integrity, efficiency and licensing

- Rendering is demand-driven. Visible raster requests are limited to four concurrently; stale requests cannot publish tiles for an old view. GPU storage holds the current viewport plus a small basemap overview. NASA source resolution is capped at level nine.
- Native raster HTTP caching uses URLSession/URLCache (16 MB memory, 128 MB disk), app identification and ordinary HTTP cache policy. There is no bulk/offline tile downloader. [OpenStreetMap tile policy](https://operations.osmfoundation.org/policies/tiles/) still applies.
- Indexed/gray PNG and JPEG tiles are normalized through bounded ImageIO/CoreGraphics decoding before Metal texture upload. Image dimensions are checked before decompression (maximum 1,024×1,024; 2 MB compressed data). This avoids Metal's indexed-PNG decoding failure without changing the tile's orientation or reported resolution.
- Source requests have byte limits, HTTPS admission, cancellation and generation checks. Minimized windows suspend source/tile work and close media playback. Mapped queries wait for 800 ms of navigation inactivity, and old local records are removed when the view changes.
- TLE propagation uses the [Vallado C++ implementation distributed by python-sgp4](https://github.com/brandon-rhodes/python-sgp4), pinned by source commit in `native/macos/Sources/CSGP4/UPSTREAM.md`. Only C++ is vendored. Two mechanical compiler-warning fixes preserve pointer/conditional semantics; propagation equations/constants are unchanged. Near-Earth, Molniya and low-inclination geostationary results are checked against 16 vectors from the existing satellite.js engine. Per-snapshot formatting is shared instead of constructing thousands of formatters.
- Observations, estimated positions, modeled weather, scheduled launch times, catalog metadata, user notes and shader effects keep distinct provenance. Missing values remain unknown, valid reported zeros are kept, and malformed entries are rejected. Satellite visibility uses segment/ellipsoid occlusion rather than incorrectly treating all objects as surface points.
- Credentials are sent only to their corresponding allowlisted provider endpoints. FIRMS, AIS and traffic payloads are not simulated when a key is missing. Data acquisition time is never manufactured from retrieval time.
- Road selection uses tile/geometry identities rather than provider feature order, so refreshing/reordering traffic tiles cannot silently select a different road. Duplicate geometry within a tile is rejected.
- Annotation files and workspace imports are limited to 2 MB, 500 annotations and 2,000 vertices/annotation; duplicate identifiers and invalid coordinates are rejected. Files are saved atomically. An import persists validated annotations before replacing the visible workspace; a failed save leaves current work intact. Corrupt existing annotation files are retained for recovery.
- San Francisco neighborhood boundaries have been removed from the native source list, renderer and resource package. Previously exported workspace files and view links ignore that removed source and its tracked identifier while preserving the other settings and user annotations; unknown source names still fail validation.
- `native/macos/scripts/sync-reference-data.mjs` reproducibly copies the existing reference layers and generates the enabled transit catalog. `update-orbit-fixtures.mjs` regenerates comparison vectors using the legacy engine. These are development tools, never application runtime dependencies.
- The source code is MIT. Bundled datacenters/dams remain ODbL, and TeleGeography cables/landing points **CC BY-NC-SA 3.0**. The non-commercial cable data is not covered by MIT and must be removed or separately licensed for commercial use. Component notices and original dataset provenance are packaged with the application.

- 80 deterministic native tests passed with zero failures; the ordinary suite contains 88 tests, with eight public-provider checks deliberately skipped unless opted in. This includes backward compatibility for workspace documents/view links containing the removed neighborhood layer.
- All eight opt-in live checks passed on October 4: native elevation and AGI photogrammetry, plus CelesTrak, MBTA, TfL, Fintraffic, Copernicus and OSRM (208 vertices and 13 turns for the checked route). The final combined run passed 87 of 88 checks: Copernicus timed out, then passed its isolated retry with ten real products. These counts are snapshots, not guarantees about future provider availability.
- New engine checks cover ECEF round trips, tilted projection/ray agreement, reverse-depth draw-order independence on the actual Metal GPU (solid and textured shaders), displaced-eye collision, tilted/date-line tile coverage, exact Terrarium channel decoding, terrain picking, local GLB transforms and credits, visible-mesh picking masks, transparent/opaque material semantics, cancellation, unsupported/escaped/missing local content, and backward-compatible camera/terrain state. Real Mont Blanc elevations ranged from 1718.74 to 4789.81 m in the checked z12 tile; real AGI content streamed a 16,744-vertex mesh with a 1024×1024 texture and a successful geometry hit. Counts and coverage vary with view and provider availability.
- Native tests cover SGP4 verification/legacy comparisons, elevated-object visibility, real reference admission/provenance, FIRMS UTC/confidence/missing values, camera URL admission, Sentinel metadata, bounded GTFS/MVT wire parsing and geometry, stable road selection across refreshes, unavailable AIS values, actual routing turns, retained-fix playback, share-state validation, local persistence, corrupt/oversized documents and failed replacements that preserve existing data. - Existing web regression tests passed: 3,899 passed, one skipped, zero failures. The existing runner skipped two allocation microbenchmarks because their budgets require Node 24 and this machine uses Node 26.8.1.
- FIRMS, AISStream and TomTom credential-dependent live connections have not been exercised with user keys. Their parsers, bounded requests and missing-key/error handling are implemented and tested; credential storage has not been tested by saving a real user secret.
- October 4 native UI testing exercised real AGI textured geometry (four meshes at the focused view), roof picking (307.2 m rendered height), heading/tilt controls and attribution, source removal, Photon navigation to Mont Blanc, elevated terrain picking (4368.2 m at the checked point), terrain off/on and continued USGS source loading.
