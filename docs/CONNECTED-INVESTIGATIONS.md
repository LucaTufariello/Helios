# Connected investigations

Mission Control now connects a shared asset registry to each mission's retained evidence, findings, follow-up and briefing. A mission remains the case; existing missions and sites are never automatically merged or converted.

## Work through a case

1. Create/select a mission in **Mission Control**. Put the case question in **Overview**. In **Investigation**, choose **Edit investigation state and conclusions** to record completion criteria, a conclusion and unresolved questions. States are Open, In review and Closed. Closing with unfinished tasks, unresolved findings/questions or active inbox entries requires an explicit closure rationale.
2. Create an area or import a saved site using the existing Areas workflow. Attach relevant source snapshots and optical/radar products to the mission. The source libraries and raster files remain separate.
3. Open **Asset registry**, or choose **Register / link shared asset** in a dossier. **Register source / area** creates a stable identity from an area, a mission's saved site/source snapshot, or manually supplied coordinates. Check the name, aliases, category, boundary, identifiers and citations before saving. This changes the profile registry, not the mission.
4. Select an existing asset and choose **Link / adopt selected asset**. Choose the relevant case area, or case-wide scope. This appends a retained version to the case. Repeat for other assets. The same identity can be adopted by multiple missions.
5. Add **Part of**, **Connected to** or **Depends on** relationships in the registry. Part of and Depends on point from the first asset to the second. Supply a source citation for every dependency; reviewed relationships require evidence and rationale. Optional validity dates use YYYY-MM-DD. Adopt both endpoint assets before adopting the relationship into the case.
6. Review the association suggestions in Asset registry. Each explains a geographic overlap or exact provider-qualified identifier match. **Approve selected association** retains the evidence snapshot and reason. Suggestions do not save themselves. Geographic overlap never creates an infrastructure dependency.
7. Explore **Connections**. The default graph uses adopted case versions. Switch to Current registry to inspect live registry information. Search names, aliases or IDs; select a root and expand the hop count. Each displayed neighborhood is limited to 100 nodes and 200 edges. A truncation notice explains when a limit is reached. Wheel to zoom, drag to pan, and use Fit. Select a node to inspect relationships, approved evidence and linked findings, focus its location on the map, or open its linked area dossier.
8. Open **Findings** and create a claim, or explicitly draft one from an observation, a monitoring inbox entry or a selected SAR candidate. Dossier observations also expose a draft action. Original identities, candidate/model information and available quality limitations are retained. Drafts begin Unreviewed and their source citations begin as Context.
9. Edit a finding to select the relevant retained asset versions and areas, describe its time context and alternative explanations, and classify citations as Supporting, Contradicting or Context. Retain additional mission evidence or supply a document/URL citation. A new manual citation starts as Context; save it, then assign its role. Review as Supported, Uncertain or Dismissed with a rationale. Supported requires at least one supporting citation. It remains an analyst judgment.
10. Changing a reviewed claim, time context, alternative explanations, asset/area links or citations resets it to Unreviewed. Save the edited version before reviewing it again. Earlier decisions, claims and citation links remain in the record. The detail pane displays earlier decisions; the manifest retains their full versions.
11. Use **Create follow-up** on a finding. The task records its finding origin. In the task editor, set an optional local owner label and prerequisite tasks. Cycles are rejected. A dependent task cannot finish until every prerequisite is done; a completed prerequisite cannot be reopened while a completed task depends on it. Remove dependency links explicitly before deleting a referenced task.
12. Choose **Export briefing**, select findings explicitly, optionally capture the current map, and **Prepare preview**. Preparation freezes the case information and checks local evidence previews in a background job. Read the preview, including missing evidence and conflicting sources. Choose **Export frozen PDF + manifest** and a parent directory. A new briefing folder contains both completed files. Preparing/exporting does not query providers or change review states.

## Preserve historical context

The registry is stored under the desktop profile at `Registry/assets.json`. Its version-1 JSON document is limited to 8 MB, 2,000 assets and 5,000 relationships. Saves use atomic publication, a last-good `.backup`, a shared lock path and conflict detection. If another process changes the file, reload it before editing. An unreadable registry is preserved; case snapshots remain available independently.

The optional `brief.investigation` version-1 extension stores case metadata, asset/relationship snapshots, citations, approved associations and findings. Limits are 1,000 snapshots, 1,000 citations, 1,000 associations and 200 findings per mission, with up to 100 retained review revisions per finding. The existing 8 MB mission-library limit still applies. Existing evidence kinds and IDs are unchanged.

Registry edits show update notices beside historical case snapshots. To use an update, select the live asset and explicitly adopt its current version. Earlier versions cited by findings remain retained. Archive registry assets/relationships instead of deleting their history. Archiving a live record does not rewrite existing case snapshots. Removing a live area, source item, observation or resolved monitoring entry does not erase the finding's retained source context.

A case opened on another machine can be examined without that machine's registry. **Preview registry import from this case** shows exact incoming/current values and conflicts before saving. Approval imports missing identities; conflicts replace registry values as new revisions. No automatic import occurs. Local raster files are not embedded in mission JSON and may be unavailable on another machine.

## Briefing contents and reproducibility

The native Qt exporter generates A4 pages without a Python PDF environment. The PDF includes the question, completion state, adopted assets and relationships, explicitly selected findings and rationale, conflicting citations, uncertainties, source/capture dates, limitations, available previews and unfinished tasks. Map context is an explicitly captured display image; its capture time is not a satellite acquisition time or a scientific georeference.

The version-1 `org.helios.investigation-briefing` manifest includes selected finding versions and their prior reviews, retained asset/relationship/citation snapshots, source IDs, recorded fingerprints, derivation references, external file references and availability at freeze time. It contains case-wide retained context and tasks alongside the selected findings. The case-document SHA-256 identifies the source mission; the content SHA-256 identifies the frozen manifest content, and the completed manifest records the PDF SHA-256. A hash identifies recorded bytes and does not authenticate their author or prove source accuracy. PDF metadata may differ between separate exports.

A changed local product fingerprint is flagged rather than silently substituted. Missing files remain visible. Existing evidence without a recorded fingerprint is identified accordingly. Raster files remain external; preserve them separately if you need to reproduce scientific processing. Preview processing is bounded to 24 images / 64 MB decoded, and exports to 400 pages. Omitted previews are identified in the availability record. No export replaces an earlier briefing folder.

This is local single-user software. Owner labels are local labels, review decisions are human judgments, and retained history is not an authenticated collaboration system or a tamper-proof audit.

## Platform and acceptance checks

The investigation workbench uses shared Qt Widgets on Linux and macOS. Swift persistence models preserve the investigation extension, historical citations, registry records and task prerequisites. A fresh macOS build/run and cross-platform round-trip remain required before declaring Mac acceptance; use the [Mac validation handoff](MAC-INVESTIGATIONS-CHECKS.md) when ready. The Linux test/packaging results are recorded in `output/qa/investigations-20261020/`; generated evaluation data is labeled and does not demonstrate satellite-analysis accuracy on a real facility.
